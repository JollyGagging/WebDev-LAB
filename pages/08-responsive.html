Module 08

Responsive Design

Your page needs to work beautifully on a 320px phone and a 4K monitor. Media queries, fluid typography with clamp(), responsive images, viewport units, and mobile-first strategy.

01

Mobile-First Approach

Write your base CSS for the smallest screen first. Then use min-width media queries to progressively enhance for larger screens. This is mobile-first.

Mobile-First vs Desktop-First
✅ Mobile-First (Preferred)
/* Base: mobile (single column) */
.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

/* Bigger screens get more columns */
@media (min-width: 600px) {
  .grid {
    grid-template-columns: 1fr 1fr;
  }
}

@media (min-width: 1024px) {
  .grid {
    grid-template-columns: 1fr 1fr 1fr;
  }
}
⚠️ Desktop-First (Avoid)
/* Base: desktop (3 columns) */
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
  gap: 16px;
}

/* Override down for smaller screens */
@media (max-width: 1024px) {
  .grid {
    grid-template-columns: 1fr 1fr;
  }
}

@media (max-width: 600px) {
  .grid {
    grid-template-columns: 1fr;
  }
}
Why mobile-first? Mobile has constraints (small screen, slower connection). Start minimal, add complexity only when you have the space for it. Also: Google indexes the mobile version of your site first.

Media Query Syntax Reference
/* Width-based (most common) */
@media (min-width: 768px) { /* 768px and wider */ }
@media (max-width: 767px) { /* 767px and narrower */ }
@media (min-width: 480px) and (max-width: 767px) { /* Range */ }

/* Orientation */
@media (orientation: portrait)  { /* Phone held upright */ }
@media (orientation: landscape) { /* Phone held sideways */ }

/* Resolution (for high-DPI / Retina displays) */
@media (-webkit-min-device-pixel-ratio: 2),
       (min-resolution: 192dpi) {
  /* Use @2x images for retina */
}

/* User preference queries */
@media (prefers-color-scheme: dark)    { /* Dark mode */ }
@media (prefers-reduced-motion: reduce) { /* Less animation */ }
@media (prefers-contrast: high)        { /* High contrast */ }
@media (hover: none)                   { /* Touch device */ }
@media (hover: hover)                  { /* Has a mouse */ }

03

Fluid Typography with clamp()

Instead of jumping between fixed sizes at breakpoints, clamp() creates fluid values that scale smoothly between a minimum and maximum based on the viewport width.

clamp() Syntax
/* clamp(minimum, preferred, maximum) */
font-size: clamp(1rem, 4vw, 2.5rem);
/*              ↑min  ↑scales  ↑max  */

/* Real-world examples */
h1 { font-size: clamp(1.8rem, 5vw, 4rem); }
h2 { font-size: clamp(1.4rem, 3.5vw, 2.5rem); }
p  { font-size: clamp(0.9rem, 2vw, 1.1rem); }

/* Padding that scales too */
.hero {
  padding: clamp(2rem, 8vw, 8rem);
}

/* Gap that adjusts */
.grid {
  gap: clamp(12px, 3vw, 32px);
}

04

Viewport Units

Viewport units are relative to the browser window size — not the parent element. Useful for full-screen sections and responsive sizing without media queries.

Viewport Unit Reference
vw
1% of viewport width
100vw = full window width
Full-width headers, horizontal spacing
vh
1% of viewport height
100vh = full window height
Full-screen hero sections
vmin
1% of the smaller dimension
Phone portrait: 1vmin = 1vw
Square elements that scale with orientation
vmax
1% of the larger dimension
Phone portrait: 1vmax = 1vh
Background text / oversized decorative elements
dvh
Dynamic viewport height
Adjusts for mobile browser chrome
Modern mobile full-screen — use over 100vh
svh
Small viewport height
The smallest possible viewport size
Ensures content never goes behind browser UI
100vh on Mobile Problem
⚠️ Mobile Safari Problem: 100vh on mobile includes the browser's address bar height, which disappears when you scroll. This causes the hero section to be too tall. Use 100dvh instead — it dynamically adjusts. 
/* Old way — causes overflow on mobile */
.hero { height: 100vh; }

/* Modern fix — use dynamic viewport height */
.hero { height: 100dvh; }

/* Fallback for older browsers */
.hero {
  height: 100vh; /* fallback */
  height: 100dvh; /* modern override */
}
05

Responsive Images

Don't serve a 3000px image to a 375px phone screen. Use srcset and sizes to let the browser pick the right image automatically.

srcset — Serve the Right Resolution
<!-- Browser picks best image based on screen size & DPR -->
<img
  src="image-800.jpg"              <!-- fallback -->
  srcset="
    image-400.jpg  400w,           <!-- 400px wide version -->
    image-800.jpg  800w,           <!-- 800px wide version -->
    image-1600.jpg 1600w           <!-- 1600px wide version -->
  "
  sizes="
    (max-width: 600px) 100vw,     <!-- phones: full width -->
    (max-width: 1024px) 50vw,     <!-- tablets: half width -->
    33vw                           <!-- desktop: 1/3 width -->
  "
  alt="Description"
  width="800"
  height="600"
  loading="lazy"
>
How it works: The browser knows the image will be 50vw on tablet. On a Retina (2x DPI) tablet at 768px viewport, that's 384px × 2 = 768px needed. It picks the 800w version as the best fit.
<picture> — Art Direction

Use <picture> when you want to show completely different images at different sizes — not just different resolutions of the same image.

<picture>
  <!-- Portrait crop for mobile -->
  <source media="(max-width: 600px)"
          srcset="hero-portrait.jpg">

  <!-- Landscape crop for tablet -->
  <source media="(max-width: 1024px)"
          srcset="hero-landscape.jpg">

  <!-- WebP for modern browsers -->
  <source type="image/webp"
          srcset="hero.webp">

  <!-- Default fallback -->
  <img src="hero.jpg" alt="Hero image"
       width="1200" height="600">
</picture>
CSS max-width Pattern

The simplest responsive image technique — ensure images never overflow their container.

/* Apply globally in your reset/base CSS */
img {
  max-width: 100%;
  height: auto; /* Maintain aspect ratio */
  display: block; /* Remove inline gap below images */
}

/* Responsive container patterns */
.full-width-img {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

.thumbnail {
  width: 100%;
  max-width: 300px;
  aspect-ratio: 1;
  object-fit: cover;
}
06

Responsive Layout Patterns

auto-fill / auto-fit — Truly Responsive Grid

The most powerful responsive grid pattern — no media queries needed at all. The browser figures out how many columns fit.

/* auto-fill: always creates columns, even empty ones */
.grid-fill {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 16px;
}

/* auto-fit: collapses empty columns, items stretch */
.grid-fit {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 16px;
}

Responsive Typography Scale

A complete fluid type scale using clamp() — define it once in :root, use everywhere.

:root {
  --text-xs:   clamp(0.64rem, 1.5vw, 0.75rem);
  --text-sm:   clamp(0.8rem,  1.8vw, 0.875rem);
  --text-base: clamp(0.9rem,  2vw,   1rem);
  --text-lg:   clamp(1rem,    2.5vw, 1.125rem);
  --text-xl:   clamp(1.1rem,  3vw,   1.25rem);
  --text-2xl:  clamp(1.2rem,  3.5vw, 1.5rem);
  --text-3xl:  clamp(1.5rem,  4vw,   1.875rem);
  --text-4xl:  clamp(1.8rem,  5vw,   2.25rem);
  --text-5xl:  clamp(2rem,    6vw,   3rem);
}

Container Queries — The Future
New in 2023: Container queries let you style elements based on their parent container's size — not the viewport size. Perfect for reusable components. 
/* Mark the container */
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

/* Query the container */
@container card (min-width: 400px) {
  .card {
    display: flex; /* Horizontal layout when wide enough */
    flex-direction: row;
  }
  .card-image {
    width: 200px;
    flex-shrink: 0;
  }
}

07

Responsive Design Checklist

Before You Ship — Check These
✅
Viewport meta tag — <meta name="viewport" content="width=device-width, initial-scale=1.0"> in every HTML file
✅
Images have max-width: 100% — no overflow on small screens
✅
Images have width and height attributes — prevents CLS
✅
No horizontal scrollbar on mobile — check at 375px width
✅
Touch targets at least 44×44px — buttons and links must be tappable
✅
No fixed widths in px for layout — use %, fr, or min/max with clamp()
✅
Fonts readable on mobile — minimum 16px base to prevent zoom on iOS
✅
Test with DevTools device emulation — check at 375px, 768px, 1280px at minimum
✅
Check with real device — DevTools isn't perfect, always test on a real phone
✅
prefers-reduced-motion — disable heavy animations for users who prefer it
