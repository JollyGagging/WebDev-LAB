Module 06

SEO & Semantic HTML

Search engines can't see your page like a human. Learn to write HTML that both browsers and bots understand — through semantic elements, meta tags, structured data, and Core Web Vitals.

01

Semantic HTML

Semantic elements carry meaning. Instead of a generic <div>, you use tags that describe the content's purpose — making it easier for screen readers, search crawlers, and future developers.

div Soup vs Semantic HTML
❌ Div Soup — Meaningless
<div class="header">
  <div class="nav">...</div>
</div>
<div class="main">
  <div class="article">
    <div class="title">Heading</div>
    <div class="text">Content</div>
    <div class="sidebar">...</div>
  </div>
</div>
<div class="footer">...</div>
✅ Semantic HTML — Clear Structure
<header>
  <nav>...</nav>
</header>
<main>
  <article>
    <h1>Heading</h1>
    <p>Content</p>
    <aside>...</aside>
  </article>
</main>
<footer>...</footer>
Semantic Elements Reference
<header> Site header or article header. Contains logo, nav, intro.
<nav> Navigation links — main menu, breadcrumbs, pagination.
<main> Dominant content of the page. Only ONE per page.
<article> Self-contained content: blog post, product card, comment.
<section> Thematic grouping of content, usually with a heading.
<aside> Content tangentially related to main content. Sidebars, callouts.
<footer> Site footer or section footer. Links, copyright, contact.
<figure> + <figcaption> Images, diagrams, code blocks with captions.
<time datetime=""> Machine-readable dates/times. Helps search engines.
<address> Contact information for the nearest article/body ancestor.
Heading Hierarchy — Critical for SEO
Rule: Every page must have exactly ONE <h1>. Don't skip heading levels. Don't use headings just for visual size — use CSS for that.
h1 — Page title. One per page. Your main keyword goes here.
h2 — Major section headings. Multiple allowed.
h3 — Subsections within h2.
h4 — Sub-subsections within h3.
h5 — Rarely needed. Consider restructuring if you're using these.
h6 — Very rarely needed. Don't force the hierarchy. 
<!-- ✅ Good heading structure -->
<h1>The Ultimate Guide to CSS Grid</h1>
  <h2>What is CSS Grid?</h2>
  <h2>Grid Container Properties</h2>
    <h3>grid-template-columns</h3>
    <h3>grid-template-rows</h3>
  <h2>Grid Item Properties</h2>
02

Meta Tags

Meta tags live in <head> and aren't visible on the page — but search engines and social platforms read them to understand and display your content.

Essential Meta Tags
<head>
  <!-- Character encoding — ALWAYS first -->
  <meta charset="UTF-8">

  <!-- Mobile viewport control -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <!-- Page title — most important SEO element (50-60 chars) -->
  <title>Learn CSS Grid | WebDev Lab</title>

  <!-- Description shown in search results (150-160 chars) -->
  <meta name="description" content="A practical guide to CSS Grid layout...">

  <!-- Tell bots to index this page and follow its links -->
  <meta name="robots" content="index, follow">

  <!-- Author -->
  <meta name="author" content="Your Name">

  <!-- Canonical — tell search engines this is the "real" URL -->
  <link rel="canonical" href="https://yoursite.com/css-grid">
</head>
Open Graph Tags — Social Sharing

When someone shares your page on Twitter, LinkedIn, or Facebook, these tags control what the preview card shows. Without them, the platform guesses — often badly.

<!-- Open Graph (Facebook, LinkedIn, WhatsApp, etc.) -->
<meta property="og:title" content="The Ultimate CSS Grid Guide">
<meta property="og:description" content="Learn CSS Grid from scratch...">
<meta property="og:image" content="https://yoursite.com/og-image.png">
<meta property="og:url" content="https://yoursite.com/css-grid">
<meta property="og:type" content="article">

<!-- Twitter Card -->
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="The Ultimate CSS Grid Guide">
<meta name="twitter:description" content="Learn CSS Grid from scratch...">
<meta name="twitter:image" content="https://yoursite.com/og-image.png">

03

Core Web Vitals & CLS

Google measures page experience with Core Web Vitals — real-world performance metrics that affect your search ranking.

The Three Core Web Vitals
LCP
Largest Contentful Paint
How fast does the main content load? Target: under 2.5s
Optimize: Lazy-load offscreen images, use loading="lazy"
FID / INP
Interaction to Next Paint
How fast does the page respond to input? Target: under 200ms
Optimize: Minimize JavaScript blocking the main thread
CLS
Cumulative Layout Shift
How much does content jump around while loading? Target: under 0.1
The main one to fix with HTML/CSS — see below!
Cumulative Layout Shift (CLS) Deep Dive

CLS happens when elements load late and push content down. The most common culprits: images without dimensions, ads that load in, web fonts that swap, and embeds without reserved space.

❌ Causes Layout Shift
← This text is here
Image loads here... later
← This text gets PUSHED DOWN when image loads
<!-- No dimensions = CLS -->
<img src="photo.jpg" alt="photo">
✅ Prevents Layout Shift
← This text stays put
Space reserved while image loads
← This text doesn't move
<!-- Width + height reserves space -->
<img src="photo.jpg" alt="photo"
     width="800" height="600">
The aspect-ratio Fix for CLS

The modern way to reserve space for images and videos — use CSS aspect-ratio. The browser reserves the correct height before the image loads.

/* Responsive image that reserves space — no CLS */
.responsive-img {
  width: 100%;
  aspect-ratio: 16 / 9; /* Browser reserves this height immediately */
  object-fit: cover;
  background: #eee; /* Placeholder color while loading */
}

/* For iframes (YouTube embeds, maps) */
.embed-container {
  aspect-ratio: 16 / 9;
  width: 100%;
}
.embed-container iframe {
  width: 100%;
  height: 100%;
}

Skeleton Screens — Loading Placeholder

Instead of blank white space while content loads, show animated skeleton placeholders. Pure CSS shimmer effect:

@keyframes shimmer {
  0%   { background-position: -468px 0; }
  100% { background-position: 468px 0; }
}

.skeleton {
  background: linear-gradient(
    to right,
    #eee 8%, #ddd 18%, #eee 33%
  );
  background-size: 800px 100%;
  animation: shimmer 1.5s linear infinite;
}
04

Accessibility & ARIA

Accessible HTML is better for SEO too. Screen readers and search crawlers both parse the same DOM — fixing one often fixes the other.

Critical Accessibility Rules
✅
Always add alt text to images 
<img src="dog.jpg" alt="Golden retriever playing in park">
<!-- Decorative only: -->
<img src="divider.png" alt="">
✅
Use lang attribute on <html> 
<html lang="en">
✅
Label all form inputs 
<label for="email">Email Address</label>
<input type="email" id="email" name="email">
✅
Focus styles — never remove outline without a replacement 
/* ❌ Don't do this */
*:focus { outline: none; }

/* ✅ Do this instead */
*:focus-visible {
  outline: 3px solid var(--accent2);
  outline-offset: 2px;
}
✅
Use ARIA landmarks and roles where semantic HTML isn't enough 
<!-- aria-label for non-obvious elements -->
<button aria-label="Close modal">✕</button>

<!-- aria-describedby for extra context -->
<input aria-describedby="pw-hint">
<p id="pw-hint">Must be 8+ characters</p>

<!-- aria-live for dynamic content -->
<div aria-live="polite">3 results found</div>
Color Contrast

WCAG requires a contrast ratio of at least 4.5:1 for normal text, 3:1 for large text.

Fail: 1.5:1
Fail: 2.1:1
Pass (large): 3.2:1
Pass (normal): 5.1:1
Best: 12:1+
05

Structured Data & Rich Results

Structured data helps Google show rich results — star ratings, FAQ dropdowns, breadcrumbs, and event info — directly in search results.

JSON-LD Structured Data (Recommended)
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "How to Learn CSS in 30 Days",
  "author": {
    "@type": "Person",
    "name": "Your Name"
  },
  "datePublished": "2024-01-15",
  "description": "A practical CSS learning guide...",
  "image": "https://yoursite.com/article-image.jpg"
}
</script>
Rich Result Types
⭐ Reviews
schema.org/Product
Shows star ratings in search results
❓ FAQ
schema.org/FAQPage
Expandable questions in search
🍞 Breadcrumbs
schema.org/BreadcrumbList
Shows page path in URL line
📅 Events
schema.org/Event
Shows date/location in search
🏢 Organization
schema.org/Organization
Adds knowledge panel data
📝 Article
schema.org/Article
Better article presentation
🔧 Tool: Use Google's Rich Results Test at search.google.com/test/rich-results to validate your structured data. And Google Search Console to monitor how your pages appear in search.
